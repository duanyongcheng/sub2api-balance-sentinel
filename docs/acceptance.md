## 部署边界

尚未连接用户现有 Sub2API、配置生产域名 / 反向代理、进行生产部署或独立安全审计。上述软件与隔离测试证据不替代这些环境工作。

上线前由部署者完成：

1. 确认实际 Sub2API 版本、管理员 API Key 权限、幂等去重和余额历史行为。管理员合规确认必须自行阅读和处理，工具不会替真实管理员接受条款。
2. 在受保护的服务器文件 / Secret 中注入凭据。不要通过聊天、命令参数、工单或日志交付 Key；不要给哨兵上游数据库账号。
3. 保持默认 loopback 发布；远程使用 HTTPS 反向代理并启用 HSTS，设置 `AUTH_SECURE_COOKIES=true` 与精确的 `ALLOWED_HOSTS`，优先叠加 VPN / 来源限制。
4. 妥善保管初始管理员恢复材料和数据卷的受保护备份；如果主动启用 TOTP，账户加密密钥与账本分开保管。Linux 上只允许容器 UID 1000 与必要运维身份读取挂载的 Secret。
5. 先保持 `AUTO_TOPUP_ENABLED=false` 观察，核对用户与金额，再用测试用户完成一次真实收支核验，最后按业务需要开启自动加额。
6. 正常停止使用 Compose 的宽限期。强杀、断电或超时后，保留并核实 `pending` / `unknown`，不要清空未决记录或自动补发。
